A.2

Recover Homographies

A homography H maps a point (x, y) in one image to (x′, y′) in the other, with 8 degrees of freedom (the bottom-right entry is fixed to 1).

Setting up the linear system

For one correspondence, x′ = (h₁x + h₂y + h₃) / (h₇x + h₈y + 1) and y′ = (h₄x + h₅y + h₆) / (h₇x + h₈y + 1). Multiplying out the denominator gives two equations that are linear in h₁…h₈:

h₁x + h₂y + h₃ − h₇·x·x′ − h₈·y·x′ = x′
h₄x + h₅y + h₆ − h₇·x·y′ − h₈·y·y′ = y′

Each pair of points adds 2 rows to A (2n × 8) and 2 entries to b (2n). With exactly 4 pairs the system has a single solution. With more pairs it is over-determined, so I solve it with least squares ( np.linalg.lstsq ), which spreads small clicking errors over all the points instead of letting one bad point decide everything.

computeH(im1_pts, im2_pts) 
def build_system(im1_pts, im2_pts):
    A, b = [], []
    for (x, y), (xp, yp) in zip(im1_pts, im2_pts):
        A.append([x, y, 1, 0, 0, 0, -x * xp, -y * xp]); b.append(xp)
        A.append([0, 0, 0, x, y, 1, -x * yp, -y * yp]); b.append(yp)
    return np.array(A), np.array(b)

def computeH(im1_pts, im2_pts):
    A, b = build_system(im1_pts, im2_pts)
    h, *_ = np.linalg.lstsq(A, b, rcond=None)
    return np.append(h, 1.0).reshape(3, 3)

A.3

Warp the Images (Rectification)

I use inverse warping : for every pixel of the output, I look up where it came from in the source with H⁻¹ and sample there. This avoids the holes you get from forward warping.

Inverse warp (core of warpImage) 
def corner_bounds(shape, H):           # output canvas = bounding box of the warped corners
    h, w = shape[:2]
    c = np.array([[0,0,1],[w-1,0,1],[w-1,h-1,1],[0,h-1,1]], float).T
    p = H @ c; p = p[:2] / p[2]
    return int(np.floor(p[0].min())), int(np.floor(p[1].min())), int(np.ceil(p[0].max())), int(np.ceil(p[1].max()))

def _source_coords(H, bounds):          # for every output pixel, where is it in the source?
    x0, y0, x1, y1 = bounds
    xs, ys = np.meshgrid(np.arange(x0, x1 + 1), np.arange(y0, y1 + 1))
    Q = np.linalg.inv(H) @ np.stack([xs.ravel(), ys.ravel(), np.ones(xs.size)])
    return (Q[0] / Q[2]).reshape(xs.shape), (Q[1] / Q[2]).reshape(xs.shape)

Interpolation

Nearest neighbor rounds the source coordinate (u, v) to the closest pixel. It is very simple and fast, but edges look jagged (stair steps). Bilinear takes the 4 neighboring pixels and mixes them with weights (1−a)(1−b), a(1−b), (1−a)b, ab, where a and b are the fractional parts of u and v. It is a little slower but the edges are smooth. Pixels whose source coordinate falls outside the image are marked invalid and become transparent (alpha = 0), which I need later for blending.

A.4

Blend the Images into a Mosaic

I warp every image into the middle (reference) image’s frame with its H, make a big canvas that fits all of them, and blend where they overlap. I tried two methods: feathering and a two-band (Laplacian-style) blend .

Blending methods

Feathering: every image gets a weight equal to the distance to its nearest border (so it is 0 at the edge and large in the middle), warped together with the image. The mosaic is the weighted average Σwᵢ·Iᵢ / Σwᵢ. It hides the exposure seam but averages misaligned things, so small misalignments show up as ghosts.

Two-band: I split each warped image into a low-frequency band (Gaussian blur, σ = 15) and a high-frequency band (image minus low). The low band is blended with the soft weights above (smooth transition over a long distance), and the high band is taken from the image with the larger weight at each pixel (hard transition, so details do not get averaged into ghosts). Then I add the two bands back.

What this taught me

A homography is exactly right only for (1) a pure camera rotation or (2) a planar scene. My photos are never a perfect rotation (I am holding a phone in my hands), so objects at very different depths show small errors. It is also very sensitive to point quality: moving one clicked point by a few pixels visibly changes the far end of the mosaic.

A B&W

Cylindrical Projection

A planar mosaic gets stretched a lot at the edges (see the bow-tie tennis result). With a cylindrical projection, every photo is first re-projected onto a cylinder around the camera. After that, a camera pan turns into a simple 2D shift, so I only need a small rigid alignment instead of a full homography.

Math

With focal length f (in pixels) and the image center (x_c, y_c), the cylinder coordinates are θ = atan((x − x_c)/f) and h = (y − y_c)/√((x − x_c)² + f²). In the output image, x′ = f·θ + x_c and y′ = f·h + y_c. I implement it as an inverse warp: for each output pixel, x = f·tan(θ) + x_c and y = f·h/cos(θ) + y_c, and then I sample the source with bilinear interpolation.

I do not know f, I let the program choose it: it maps my clicked correspondences onto the cylinder for many values of f and keeps the f for which “cylinder + rotation + translation” fits the points best (the smallest residual).

Cylindrical warp 
def cylindrical_warp(im, f):
    h, w = im.shape[:2]
    xc, yc = (w - 1) / 2, (h - 1) / 2
    out_w = int(2 * f * np.arctan(xc / f)) + 1
    xs, ys = np.meshgrid(np.arange(out_w), np.arange(h))
    theta = (xs - (out_w - 1) / 2) / f
    hh = (ys - yc) / f
    u = f * np.tan(theta) + xc            # inverse mapping: cylinder pixel -> source pixel
    v = f * hh / np.cos(theta) + yc
    out, valid = sample_bilinear(im, u, v)
    return out, valid.astype(np.float64)

Part B: Feature Matching for Autostitching
B.1

Harris Corner Detection and ANMS

I wrote a single-scale Harris detector from scratch. The photos are resized so the longest side is 1200 px.

Harris

I blur the gray image (σ = 1), take Sobel derivatives Ix and Iy, and smooth the products Ix², Iy², IxIy with a Gaussian (σ = 1.5) to get the matrix M at each pixel. I use the harmonic mean of the eigenvalues, f = det(M) / trace(M), which is what Brown et al. use. Then I keep local maxima in a 5×5 neighborhood with f above 1% of the maximum, and I throw away corners within 20 px of the border (I need a 40×40 window around each corner later).

ANMS (Adaptive Non-Maximal Suppression). Plain Harris corners bunch up in textured areas (the trees), so most of the corners come from one place. For every corner i, I compute a suppression radius rᵢ = the distance to the nearest corner j that is clearly stronger (fᵢ < 0.9·fⱼ). Then I keep the 500 corners with the biggest radius. The result is strong corners that are also spread over the whole image. The strongest corner has radius ∞, so it is always kept. For speed I only run ANMS on the 6000 strongest candidates.

ANMS 
def anms(xs, ys, strength, n_keep=500, c_robust=0.9, max_candidates=6000):
    order = np.argsort(-strength)[:max_candidates]
    xs, ys, s = xs[order], ys[order], strength[order]
    pts = np.stack([xs, ys], axis=1).astype(np.float64)
    r = np.full(len(s), np.inf)
    for a in range(0, len(s), 1000):
        d = cdist(pts[a:a+1000], pts, "sqeuclidean")
        stronger = s[a:a+1000, None] < c_robust * s[None, :]   # only clearly stronger corners can suppress i
        d[~stronger] = np.inf
        r[a:a+1000] = d.min(axis=1)
    keep = np.argsort(-r)[:n_keep]
    return xs[keep], ys[keep], r[keep]

B.2

Feature Descriptor Extraction

For every kept corner I take a 40×40 window, blur it, and sample an 8×8 patch from it (every 5th pixel). I do not use rotation invariance here.

How

I first blur the whole gray image with a Gaussian (σ = 2), then sample the 8×8 grid with spacing 5 pixels from the 40×40 window (bilinear interpolation). Sampling from a big window gives a blurry, low-frequency descriptor, so small shifts of the corner (no sub-pixel accuracy) and small misalignments do not change it much. Finally I bias/gain-normalize: subtract the mean and divide by the standard deviation, so the descriptor does not care about brightness or contrast changes between the photos.

extract_descriptors 
def extract_descriptors(im, xs, ys, window=40, size=8, blur_sigma=2.0):
    g = ndi.gaussian_filter(to_gray(im), blur_sigma)
    step = window // size                                   # 5 pixels between samples
    offs = (np.arange(size) - size / 2 + 0.5) * step
    descs = []
    for x, y in zip(xs, ys):
        gx, gy = np.meshgrid(x + offs, y + offs)
        patch = ndi.map_coordinates(g, [gy, gx], order=1, mode="nearest")
        descs.append(((patch - patch.mean()) / (patch.std() + 1e-8)).ravel())   # bias/gain normalization
    return np.array(descs)

Result

The 8×8 descriptor is a very blurry version of the 40×40 window, but it keeps the big structure: for the fence/net corner (second from the right) the bright horizontal band shows up as a clear light/dark split, and the cloud in the last column becomes one bright blob. Descriptors from the textured bushes look like noise, which is why those are harder to match. Because of the normalization, a bright patch and a dark patch with the same structure end up with the same descriptor.

B.3

Feature Matching

For each descriptor in image 1 I find its two nearest neighbors in image 2 (by squared difference, SSD) and use Lowe’s ratio test.

Ratio test

A match is accepted only if d₁ / d₂ < 0.6, where d₁ and d₂ are the distances to the first and second nearest neighbors. If the best match is much closer than the second best, it is probably a true match. If both are about equally far, the descriptor is ambiguous (fence and leaves look the same everywhere) and I throw it away. I used 0.6 as a compromise: it gives enough matches for RANSAC and still keeps most of the wrong ones out.

Matches and RANSAC inliers

B.4

RANSAC and Automatic Mosaics

Even after the ratio test, some matches are wrong, and least squares is very sensitive to even a few wrong points. So I use RANSAC.

4-point RANSAC (from scratch)

Repeat 3000 times: pick 4 random matches (skip the sample if three points are almost on one line), compute H from them exactly, count the matches whose transformed point is within 3 px of its partner (the inliers), and remember the best H. At the end I recompute H with least squares on all inliers of the best model. The final H uses the same computeH as in Part A, so all the warping and blending code is the same as before.

ransac_homography 
def ransac_homography(p1, p2, n_iter=3000, eps=3.0, seed=0):
    r = np.random.default_rng(seed)
    n = len(p1); best = np.zeros(n, bool)
    for _ in range(n_iter):
        idx = r.choice(n, 4, replace=False)
        if not _nondegenerate(p1[idx]): continue            # 3 collinear points -> bad sample
        H = computeH(p1[idx], p2[idx])
        err = np.linalg.norm(apply_H(H, p1) - p2, axis=1)
        inl = err < eps
        if inl.sum() > best.sum(): best = inl
    H = computeH(p1[best], p2[best])                        # final least squares on all inliers
    return H, (np.linalg.norm(apply_H(H, p1) - p2, axis=1) < eps)

B.5

Bells & Whistles: Panorama Recognition

Instead of telling the program which photos belong together and in what order, I give it an unordered pile of 10 photos and let it figure that out.

Pipeline

I shuffled 10 photos (3 tennis, 3 Yellowstone, 2 pumpkin, and 2 unrelated photos, the bear poster and the Taipei 101 canvas). For every ordered pair of photos I run the whole matching + RANSAC pipeline and record the number of ratio-test matches nₘ and RANSAC inliers nᵢ. Following Brown et al., a pair is declared to overlap if nᵢ > 5.9 + 0.22·nₘ (in both directions). The photos that are linked this way form a graph, and each connected component is one panorama .

To stitch a group, I pick the image with the most inliers as the reference, then grow a maximum spanning tree from it: at each step I add the neighbor with the strongest connection (most inliers), and compose the homographies along the tree. A single photo with no link (the unrelated ones) is reported as “not part of any panorama”.

Result

The program found exactly 3 groups with the correct members, and it correctly left the bear poster and Taipei 101 out (they have at most 23 inliers with any other photo, below the threshold). It also chose the middle photo as the reference for the tennis and Yellowstone sets by itself, because that photo has the most inliers.

There was one interesting problem. The two tennis courts look alike , so the left and the right tennis photos also match each other (44 and 37 inliers) with a wrong homography. The first time, my code walked through that bad link, the mosaic canvas exploded in size, and the program ran out of memory. Growing the tree with the strongest links first fixed it: the left–middle (117 and 122 inliers) and right–middle (89 and 79) links are used, and the weak left–right link is ignored. A weaker version of this happens for yellow_1 and yellow_3 (about 57 inliers), which only share a bit of the far horizon.

6

What I Learned

Takeaways

The part that took the most time was not the math but choosing good points: spread out, on static objects, and clicked accurately. Inverse warping with bilinear interpolation gives clean results, and the blending method matters a lot: two-band blending removed most of the ghosting that feathering left behind. The most surprising thing was how much a cylindrical projection helps for a wide scene, and how a tiny rotation in the camera (not a pure pan) can ruin a translation-only alignment. In Part B I learned that automatic matching works well when the features are spread over the image (ANMS helps a lot), that RANSAC makes the homography robust against wrong matches, and that a repeated structure (two identical tennis courts) can fool the matcher, so a recognition system should not trust every link equally.
